结构疲劳评估需要一台缺口根部弹塑性应力应变的核算服务，把 Ramberg–Osgood 本构与 Neuber 双曲线联立起来，由弹性名义应力推出缺口局部的真实应力与应变。它是单调加载下的缺口塑性计算内核，只经 HTTP 工作，没有网页，也不是材料牌号库或采购系统，与晶粒屈服、稳态蠕变这类模型无关。

本构关系取 Ramberg–Osgood 单调形式：总应变 ε = σ/E + (σ/K)^(1/n)，其中 E 为弹性模量、K 为强度系数、n 为硬化指数。塑性硬化指数、强度系数、弹性模量为非正，或应力集中系数 Kt 小于一，都要以带原因的错误返回。要内置一份 Kt=3 的圆角缺口算例：当名义应力超过比例极限后，缺口局部的真实应力应当低于按弹性外推的 Kt·σn，服务启动后可载入这份算例把弹塑性结果与弹性对照一并打出。

Neuber 关系把弹性能与真实能联系起来：σ·ε = (Kt·σn)² / E。把它与 Ramberg–Osgood 本构联立，对每个名义应力求根解出缺口根的真实应力与应变，卸载迟滞可以只做很薄的一层。求根若不收敛，要报错而不是返回一个可疑的数。这里的核心陷阱是幂次里的 1/n 不能误写成 n，否则整条塑性段全歪；另一个陷阱是进入塑性后仍旧沿用 σ = Kt·σn，让应变不再放大，那样 Neuber 的交叉规则就整体失效了。

要同时成立的关系：当名义应力保持在弹性范围内时，真实应力等于 Kt·σn、真实应变等于 σ/E；把名义应力加大到进入塑性，真实应力增长放缓、真实应变加快增长；把应力集中系数调大，同一名义应力下缺口更苛刻；当 Kt 等于一即无缺口时，Neuber 退化回单轴的 Ramberg–Osgood。服务要能处理单点名义应力的核算，也要能对一串递增的名义应力批量求解，勾勒出从弹性进入塑性的整段响应，各点求解互不影响。

把 Ramberg–Osgood 本构、Neuber 联立求根、弹性对照、批量加载序列求解、输入校验拆到彼此独立的类与模块，并配自动化测试，重点盯住弹性极限内 σ=Kt·σn 与 Kt=1 退回单轴这两条，同时验证求根不收敛时的报错路径。

实现基于 Java 17，用 Spring Boot 暴露 HTTP 接口，数值求根自己写、不依赖外部数学库。构建交给 Maven，仓库里附一个 Dockerfile 打出镜像，容器跑起来后在某个固定端口接受调用，测试与源码同仓、能在容器内跑过。类的组织按职责铺开：本构、Neuber 求根、批量序列求解、接口层各自成类成文件，别让所有逻辑堆进一个臃肿的大类。
